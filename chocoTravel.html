ちょこ旅

概要

企画開発部、2026年春みんげーチーム開発で開発したゲームです。

マリオやカービィのような3dモデルを用いながらも2次元の操作でステージを進めていく2Dアクションゲームです。 主人公のチョコレートは液体状になったり、他のお菓子をコーティングして能力を得たりと「チョコレート」であることを活かしてステージを進めていきます。

ゲームにきちんとしたチュートリアルは存在せず、マリオの1-1のようにプレイヤーに試行錯誤してもらい"気づいてもらう"設計を心がけています。

2026年5月 現在、このプロジェクトは進行中であり、ストーリーや新ステージの追加、機能の改善などをしていくつもりです。

デモプレイ映像(Stage1)

使用技術

C# / Unity / MVC設計 / DI設計 / UniRx etc...

プログラマーとしてプロジェクトに参加。

その後は以下のような部分を点々と実装しました

  • ダメージエリア(マグマ)の実装
  • ユーザーデータの管理(ScriptableObject)
  • フォントの差し替え
  • プレイヤー(チョコ)が歩いた時に擬音を出す(文字)

  • 能力でアーモンドを投射する時の矢印のデザイン
  • 敵が投げるキャンディーのモデリング
  • 能力で出す"バリア"エフェクトの作成

工夫した内容

タイトルの基盤を作る際に一番意識したのはMVC設計を踏襲しつつかつ"後から変更しやすくすること"です。

そこで次の流れに沿ってタイトルSceneを作成しました。

問題提起

    タイトルのボタンの機能をInspector上でOnclic設定するのは不親切ではないか。 また、Sceneに変更を加えた時に参照切れや設定漏れが起きやすく保守性に欠けるのではないか。

解決法

MVC設計をもとに以下のように責務を分離する

  • View: ボタンイベントの登録
  • Controller: 押した時のロジックを実装

実装したコード

ViewのScriptの一部


    //関数を登録する関数
    public void BindStart(Action action)
        => _startButton.onClick.AddListener(() => action());

ControllerのScriptの一部


    _titleUIView.BindStart(OnClickStartButton); //これをAwake()で実行する

    private void OnClickStartButton() //登録する関数
    {
        if (_hasStartedTransition) return;

        if (_isStarting)
        {
            OnWakeUpCompleted();
            return;
        }

        _isStarting = true;
        _titleUIView.SetMainMenuInteractable(start: true, settings: false, quit: false);
        _titleUIView.SelectStartButton();

        if (_animationController == null || !_animationController.SetWakeUp())
        {
            OnWakeUpCompleted();
        }
    }

結果

実際にこの設計によって以下のメリットを得られました。

  • 新たにボタンを追加する際に、コピペできるようにすることで変更が容易になった。
  • 新たにボタンを押した時の処理を実装(変更)することが容易になった。
  • Sceneの変更による設定漏れなどの人為的ミスを防止できた
    •

    以降の他の実装も基盤を作る際には"変更のしやすさ、見やすさ、使いやすさ"を念頭に実装を行いました。

    苦労した点

    一番苦労したのは"他人のコードを読むこと"です。

    他メンバーがゲーム内のエンティティをモジュール化して実装しており、簡単に敵などを実装できるようになっていました。それ自体はとてもありがたくチームの生産性を 向上させていたと思います。

    実際に20個以上のファイルで構成されていますが、少し機能を追加するだけなら数ファイルだけ理解すればいいという素晴らしい構成でした。

    一方で、バグ修正や大規模な変更となれば話は別です。20個以上のファイルの大部分を理解する必要があります。そしてその仕様を深く理解しているのは作ったメンバーのみでした。

    この経験を通して、チーム開発では機能を実装する力だけでなく、誰が見ても理解しやすいコードや設計を残すことが、長期的な開発では非常に重要だと実感しました。

    得た技術

    今回このプロジェクトに参加したことで、知識として知っていた「DI設計」や「コンポーネント指向」を実際に使用することによって”生きた技術”として吸収することができました。

    また、MVC設計についても使用したことにより、更に練度が上がったと感じています。

    そしてなにより、大量の他の人のコードを読んだ経験は自分では思いつかない設計思想に触れる貴重な経験であり、自身の総合的なスキルアップに大きく貢献してくれたと思います。

    今後はUnityやC#の技術力を高めながら、設計/保守性のことも考えられるエンジニアを目指したいです。

    また、今後も本作品の開発は続きますのでより良い完成形を目指して日々努力していきたいです。
